### ★ 与计划的重大偏差（实测推翻前提）
原计划阶段 2 假设「转化只来自武器槽、只有少数档位 → 枚举武器桶」。**实测不成立**：
全库 **2458 件**物品带转化，分布在整个 14 个槽
（melee2h/shields/caster/guns2h/swords1h/waist/focus/rings/necklaces/components），
**294 种** `(in,out,pct)` 签名。⇒ 改用「**逐件估值 + 迭代线性化**」，不做桶枚举。
估值口径：`损失比例 = X% × 源伤害占比 × (m_in − m_out)/m_in`，源伤害占比取自
**真实评估**的 `dps_by_type`（不再假设纯物理）。

### ★ 顺带修掉的真 bug
`O.key(sol)` 在退火/束搜索排序路径上 **`KeyError: 'conv_net'`** ——
`W_PEN` 缺了新维度（惩罚项是 `for k in FLOOR: W_PEN[k] * …`，两个表必须**同键集**）。
本轮的 `selftest [16]` 断言组就是抓它的。**修法**：`W_PEN` 补 `conv_net: 0.0`
（权重 0 是因为 `FLOOR['conv_net'] = -1e9` 本就「不设下限」），并加断言
「`FLOOR`/`W_DMG`/`W_PEN` 必须覆盖全部 `FKEYS`」。

### ★ 真源归属变更
`gd/dps.py`（+131 行）与 `gd/opt.py`（+458 行）的积累改动已超出「几处字符串替换」
能表达的规模 ⇒ **从迁移的 patch 步骤迁到 `sync_live.py` 的 `PAIRS`**（现 **12 对**），

## 2. 缺口分析

### 2.1 转化：算术已对，搜索是瞎的

`gd/rotation.py:apply_conversions` 实现是**正确**的：多源同源叠加、>100% 按比例分摊、
`Elemental` 均分给火冰电、两阶段化保证与哈希序无关。

问题在**搜索侧**：`gd/opt.py:off_of()` 的伤害代理是**逐槽可加的静态 15 维向量**
（OA / pierce% / phys% / bleed% / total% / crit / spd / fpie / fbleed / life / armor…）。

- 维度里**没有 cold/fire/lightning**，所以「冰冷加成 +644%」这类词条一分都拿不到；
- 逐槽可加 ⇒ 无法表达「换一把武器会**重新路由全身伤害**」这种全局耦合；
- 现在的对策是 `GD_CONV_KEEP` 环境变量**白名单过滤**（`conversionOutType` 不在名单里的候选件整体剔除）——
  这是补丁，不是模型：它只能删候选，不能给候选**正确估值**。

### 2.2 减抗：整个维度不存在

`gd/dps.py` 头部注释就写着「不含怪物抗性/护甲」。全库扫下来，减抗字段**没有任何代码消费**，
只有 `gd/gen.py` 的显示用标签映射里出现过「降抗」字样。

两个机制（已核实字段名）：

| 族 | 字段 | 出现位置 | 官方显示文本（取自标签表） | 叠加口径 |
|---|---|---|---|---|
| **A** | `defensive<类型>`（**负值**） | 技能：`mastery_skills` / `devotions` / `e_skills` / `item_skills` | `-X% 穿刺抗性` / `-X% 冰冷抗性` … | **按类型各自叠加** |
| **B-%** | `offensiveTotalResistanceReductionPercent`<br>`offensiveElemental…Percent`<br>`offensivePhysical…Percent` | 物品（60+ 件）、星座、物品技能 | `-X% 目标抗性降低` | **取最强**（不叠加） |
| **B-abs** | `offensiveTotalResistanceReductionAbsolute`<br>`offensiveElemental…Absolute` | 物品（63 件）、技能 | `-X 目标抗性`（无 %） | **叠加** |

> 依据：标签表（`data` 里的 16563 条本地化文本）里
> `DamageTotalResistanceReductionPercent` = `% 目标抗性降低`、
> `DamageTotalResistanceReductionAbsolute` = `目标抗性降低`（无 %）、
> `DefensePierce` = `{%.0f0}% 穿刺抗性`。字段族与显示文本一一对应，这是最权威的离线证据。

**A 族的值是逐级数组**（`[-3,-6,-9,…, -30]`），所以减抗强度**取决于技能等级**
⇒ 技能加点天然是决策变量。

**代价量化**（−57% 穿刺抗性，对不同类型的敌人）：

| 目标穿刺抗性 | 减抗后 | 伤害倍数 |
|---|---|---|
| 0% | −57% | **1.57×** |
| 20% | −37% | 1.71× |
| 33%（精英档） | −24% | 1.85× |
| 50%（Boss 档） | −7% | 2.14× |
| 80%（高抗 Boss） | −23% | **3.85×** |

→ 我们现在「满抗 + 线性伤害代理」的目标函数**系统性低估减抗件**，
会拿它去换「看起来更值钱」的线性 % 伤害。这是当前最大的模型误差。

### 2.3 技能点 / 星座：有模块，但不在搜索里

`gd/alloc.py`（`allocate` / `skill_budget` / `attr_budget` / `devotion_budget`）与
`gd/devotion.py`（`check_affinity` / `select_coherent` / `constellation_of`）都已实现，
但它们是**固定输入**：`gd auto` 只搜索装备，技能点与星座不参与优化。
参照构建恰恰在技能上做了关键取舍（刺骨战吼满 12 拿 −30%、夜之寒气只给 7 点），
这层自由度目前拿不到。

## 3. 方案（分四期，可独立验收）

### 阶段 1 — 减抗进伤害模型（★ 收益最大，建议先做）

1. `gd/rr.py`（新）：从装备 + 技能（按等级取值）收集三类减抗，按口径合计，
   产出 `{伤害类型: 有效减抗%}`。
2. `gd/dps.py`：在 `final_report` 的伤害汇总处加一层**敌方减伤乘区**
   `(1 - clamp(res - rr)) / (1 - res)`，`res` 来自「标称敌方抗性 profile」。
   ★ 面板数字仍按 grimtools 口径（不含敌方抗性）输出，保证可对拍；
   减抗只进**目标函数**与新增的「实战伤害」一行。
3. `gd/opt.py`：`FKEYS` 新增减抗维度（pierce_rr / phys_rr / bleed_rr …），
   权重 = 边际价值 `∂DPS/∂rr`（按当前敌方 profile 解出）。
   注意 max 语义 → 用「当前解的有效减抗」迭代 2~3 轮线性化。
4. `tools/selftest.py`：新增断言组（字段采集 / 口径 / 边际价值单调性）。

### 阶段 2 — 转化进搜索

把「武器桶」显式化：转化来源实测**只来自武器槽**，且只有少数几种
（本例 0 / 45 / 90% 三档）。方案：
先按武器对枚举转化桶 → 每个桶内伤害分量固定 → 桶内 ILP 恢复线性 → 取全局最优。
同时删掉 `GD_CONV_KEEP` 白名单 hack。

### 阶段 3 — 技能点 + 星座进联合搜索

优先只把**影响减抗的技能等级**（刺骨战吼 / 夜之寒气 / 暗杀者的标记等，全库约 10~30 个）
提为决策变量（维度最小、收益最大），星座先用现有的 `select_coherent` 出候选再评估。

### 阶段 4 — 社区构建当回归语料

`tools/gt_regress.py`：抓 N 个 grimtools 构建 → 用我们的引擎重算 → 与面板数字对拍
（OA / DA / 抗性 / 各类型伤害 / 攻速），建立**数值正确性回归**。
这是唯一能证明「我们的引擎 == 游戏」的手段，也能反向暴露更多未建模机制。
