# 减抗（RR）机制 · 联网调研 + 本库模型对拍

> 调研日期 **2026-09-20**。触发问题：「如果怪的抗性被减到负数，是增加伤害，还是锁在 0？」
> 结论已用于校验 `gd/rr.py`，并登记三处**潜伏偏差**（当前不影响 Sam）。

## 一、直接回答

★ **不锁在 0。** 敌方抗性可以减成**负数**，负值**按 1:1 放大伤害**。

```
伤害倍数（相对「不减抗」）= (100 − r) / (100 − 基础抗性)
r = 0     → 1.00×     r = −50%  → 1.50×
r = −100% → 2.00×     r = −118% → 2.18×
```

这就是为什么 GD 里减抗是**最大的乘区**：`−57% 抗性` 打在 80% 抗性的 Boss 上
⇒ `(100−23)/(100−80) = 3.85×`。

## 二、三族减抗（最容易搞混的地方）

三族**不是按数值大小排列，而是按「减抗文案的措辞」区分**，规则完全不同。
社区把措辞当判据：**看有没有 "Reduced" 这个词、有没有 `%`**。

| 族 | 游戏文案 | 典型来源 | 合计规则 | 能否低于 0 |
|---|---|---|---|---|
| **B** | `−n% <类型>抗性`（技能行，**不带独立持续时间**） | 夜之寒（暗影帷幕）、诅咒虚弱、奥莱克萨的冰冻 | **叠加**（不同技能相加） | ✔ 可以 |
| **C** | `n% Reduced target's Resistance`（**带 %、带持续时间**） | 毒蛇 Viper、乌尔托斯 | **只取最高一个**（不叠加） | ✔ 可以（见下） |
| **A** | `n Reduced target's Resistance`（**无 %、带持续时间**） | 罗文王冠、蝎狮、战争怒吼 | **只取最高一个**（不叠加） | ✔ 可以 |

**结算顺序：B → C → A**（社区 2019 年版实测共识，源自日文 wiki 测试）。

### 两个社区争议点（已厘清）

1. **C 类能不能把抗性推成负数？**
   - 旧 wiki 与部分老帖说「不能低于 0」。**这个说法已被推翻。**
   - Crate 官方论坛《Advanced Mechanics》给出修正公式：
     - 抗性为正：`r × (1 − n%)`
     - 抗性为负：`r × (1 + n%)` ← **把负值推得更深**
   - 例：`10% − 18 − 46% = −54%`，再套 C 类 30% ⇒ `−54% × 1.30 = −70.2%`。
   - ⚠ 也有 2019 年帖认为 C 类对负值**无收益**（乘法把负数拉回 0）。两派并存，
     但**官方论坛的 +n% 版本更完整**，本库按此口径实现。

2. **A 类绝对值能不能低于 0？** 能。官方论坛明言
   `Absolute = Can be reduced lower than 0%, it is additive`。

### 有没有硬下限？

- **没找到引擎级硬下限的权威证据。** 社区实例出现过 **−118%**（→ 2.18× 伤害），
  说明下限至少在 −100% 以下。
- 唯一的「−100%」说法来自第三方计算器（calculator.city）的**自设假设**，
  原文 `Assumes a minimum effective resistance of -100%` —— 是它的约定，不是官方规则。
- ⚠ 本库 `gd/rr.py::res_eff()` **钳在 −100%** ⇒ **保守**，极端减抗流会**低估**。

## 三、本库模型对拍（`gd/rr.py`）

| 项 | 官方 / 社区口径 | `gd/rr.py` 现状 | 影响 Sam？ |
|---|---|---|---|
| 负抗性放大 | 1:1，不锁 0 | ✔ `mult=(100−r)/(100−base)` | 一致 |
| B 类（键 `add`） | 叠加 | ✔ 累加 | 一致 |
| A 类（`…ReductionAbsolute`，键 `flat`） | **只取最高** | ✔ **已改为独立 `flat` 族**（2026-09-20 修，旧版混进 `add` 求和） | **不影响** |
| C 类（`…ReductionPercent`，键 `max`） | 只取最高；负值 **× (1+n%)** | ✔ **已改为负值加深**（2026-09-20 修，旧版 `×(1−n%)` 把负值拉回 0） | **不影响** |
| 顺序 | B → C → A | ✔ **已改为 B → C → A**（2026-09-20 修，旧版是 `(B+A) → C`） | 不影响 |
| 下限 | 存疑（社区见到 −118%） | `rr_floor()` 默认 **−100%（保守）**，`GD_RR_FLOOR` 可放开 | 不影响 |

### 为什么当前不影响 Sam

`python -m gd rr Sam` 实测：

```
技能/星座：物理 −4%；穿刺 −38%；冰冷 −25%；流血 −40%；混乱 −25%
装备/词缀：（无）
max 族（C 类）是否为空：True
装备折叠字段中的 RR 键：（无）
```

⇒ Sam 的**基座**（存档技能 / 星座）减抗**全部来自 B 类**（负 `defensive*` 字段），
而 **B 类的模型完全正确**。所以**锚点** `python -m gd dps Sam` **101,976 / 152,476 零漂移**
—— 这三处偏差**不会**让「当前配装的面板」漂移。

> ⚠ **但别据此说「现有报告不受影响」**：三处偏差的受害面不是基座，而是
> **优化器挑出来的方案** —— 那些方案会主动吃 A/C 装备（逐件普查见 §4.1：
> 12,717 件里 **C 族 28 件 / A 族 31 件**）。实测修正后 B 口径整段重排
> （除 `werewolf` 外 −13.6% ~ +12.1%）。

### 偏差的**触发条件**（为什么「Sam 没变」不等于「不用修」）

只要 build 里出现**装备/词缀**带的 A 类或 C 类减抗，偏差就会激活。
全库实测（`data/cache/*.js` 原始解包逐串计数）：

| 文件 | C 族（`…ReductionPercent`） | A 族（`…ReductionAbsolute`） |
|---|---|---|
| `itemdb.js`（8.3 MB） | 90 处 | 189 处 |
| `skills_json.js` | 0 | 0 |
| `monsterdb.js` | 4 | 32 |

⇒ 装备侧两族都有相当体量，**换 build / 换词缀就会踩到**。

> ⚠ 上表是**原始 JS 串计数**（「处」≠「件」：一件物品可能同时有 `Min`/`Max` 两个后缀）。
> 按 `gd.rr.rr_of()` 解析后的**权威件数**见 §4.1：C 族 **28 件** / A 族 **31 件**。

## 四、三处修复已落地（2026-09-20）

原为「待批准」，用户批准后**已实现并回归**：

1. **A 类改为「取最高」** ✔ 落地 —— `…ResistanceReductionAbsolute` 从 `add` 族拆出，
   新建 **`flat` 族**（`rr_of` / `combine` / `empty` / `add_item` / `collect_char`
   全链路带 `flat` 键），结算排在 C 类**之后**（B → C → A）。
2. **C 类对负值改为加深** ✔ 落地 —— `res_eff()` 里 `r < 0` 走 `r × (1 + pct/100)`；
   模块顶部 docstring 里「B-% 对负抗性是负收益」的错误表述已删除。
3. **下限可配** ✔ 落地 —— 新增 `rr_floor()`，读环境变量 `GD_RR_FLOOR`，
   默认 **−100%**（保守）；报告里会印出当前下限值。

配套：

- `gd/opt.py`：`rr_dims()` 与 `find_rr_skills()` 把 `flat` **折进 `rr_add` 维**
  （同量纲：都是「减多少点抗性」）—— 否则带 A 类减抗的装备在代理里是 0 分、被整类丢掉。
- `gd/dps.py`：报告的抗性表新增 `rr_flat` 列，口径说明段重写为 B→C→A 的三族表述。
- `tools/selftest.py`（[16] 组）**新增 6 条断言**：三键齐备 / C 取最高 / A 取最高且不混入
  `add` / 负值加深（官方论坛例 `−70.2%` 逐位对拍）/ 顺序 B→C→A（用 `40×0.7−8=20` 与旧版
  `(40−8)×0.7=22.4` 区分）/ 下限可配。
- 自检 **379 项全绿**、`python -m gd dps Sam` 锚点 **101,976 / 152,476 零漂移**、
  `sync_live.py` 已 `--capture`。

> ⚠ 本库对 Sam 的**结论数字一个都没变**（其减抗全为 B 族）；这项修复守的是
> **换 build / 换词缀后**的正确性。

### 4.1 修复的**实测影响面**（2026-09-20）

| 口径 | 数量 |
|---|---|
| 物品库总件数 | 12,717 |
| 含 **C 族**（`…ReductionPercent`）的物品 | **28** 件 |
| 含 **A 族**（`…ReductionAbsolute`）的物品 | **31** 件 |
| 两族都有 | 2 件 |

⇒ 只有这 **57 件**装备会踩到旧偏差。但**优化器的目标函数也走 `res_eff`**，
所以只要搜索过程中**试过**其中一件，整条 LNS 轨迹就会重排。

实测（`berserker_nightblade`，B 口径）：

| 项 | 结果 |
|---|---|
| 管线确定性（**同命令跑两次**） | 决策变量**逐位一致**，DPS 均为 75,921 ⇒ 不是随机性 |
| `gd/opt.py::rr_dims` 旧/新口径 | **0 处差异** ⇒ 那处改动是 no-op（仅防御性对齐） |
| **同一方案**在新 / 旧目标函数下 | 75,921 ／ 65,360 ⇒ **+16.2%** |

⇒ **修复前后的 B 口径数字不可直接对比**（目标函数变了）。每轮口径变更后
都要重跑普查，别拿旧 B 口径当回归基线。

### 4.2 A/B 开关

`GD_RR_C_NEG=deepen`（默认）／`=pull`（回旧行为）—— 用于对照两种社区说法。
`GD_RR_FLOOR` 调抗性下限。两者都有自检断言守着。
